# Claude review: implementation response

3 November 2026. Applies to the two [archived reviews](README.md), especially the updated real-image review of `166cab9`. Local implementation baseline: `b8a64bd`.

The changes address reproducible search, consistency and repeated-work issues. They do not retune acceptance thresholds to improve apparent phase identification. Previously exported results remain recorded results; rerunning with the new engine can produce different candidates.

## Finding-by-finding decisions

Numbers refer to the updated review's prioritized findings.

| Finding | Decision and resulting behaviour |
| --- | --- |
| 1. Rank-auto rewards smaller peak sets | Preserve the deliberately dominant-pattern mode; rename it **Auto · dominant rank** and explain the changing denominator in the selector, result flags and README. Exports add `scope`, `pool_profiles`, `pool_weight` and `selected_weight_fraction`. A fixed-pool or joint-pattern objective remains a separate experimental change. |
| 2. Automatic-scale seeds miss weaker orientations | Preserve every legacy seed, including useful c/a variants, then add at most two supplementary seeds per template. Candidates must differ by more than 2° modulo 180° and have at most 80% Jaccard overlap of supported profiles with every selected seed. These are search heuristics, not physical angular-resolution claims. |
| 3. Fixed-scale top-two angle truncation | Apply the same supplementary search after the existing two seeds. |
| 4. Strongest-peak-relative detector cutoff | Leave unchanged. The real-image review found mostly non-reproducible features below it. Recurrence/local-prominence admission needs testing before lowering the cutoff. |
| 5. Weak checks ignore smoothing and floor | Reuse the actual processed FFT detector signal and selected threshold floor. Legacy inputs without that signal reconstruct it using the recorded smoothing. The strong minimum-strength cutoff is deliberately not applied to weak maxima. Non-default settings can change weak bonuses/missing costs on rerun. |
| 6. Four-profile screen and three first-order profiles | Keep the screen; add an explanation when only three profiles are detected. Three-profile acceptance needs a separate ambiguity/noise study. The software does not infer a hexagonal structure from the count alone. |
| 7. Whole-set coverage penalizes secondary patterns | Defer scoring changes. Exploring additional seeds fixes one search limitation but cannot remove the global-coverage screen. A pair objective must count shared evidence once and charge for extra patterns. |
| 8. Finite, unequal zone libraries | Keep explicit limitations. Expanding the library and calibrating a search-size correction require benchmark controls; no new zones in this change. |
| 9. Unequal fitting flexibility | Preserve the existing overall/c/a controls. Do not invent a new complexity penalty without calibration. |
| 10. Inconsistent duplicate removal | Fixed and automatic-scale search now share zone-aware retention: near-duplicate support within a phase/zone is suppressed, while different zone labels remain alternatives. Existing shared-evidence classification still determines whether alternatives support separate patterns. |
| 11. Mean radial background | Defer median/robust-background experiments; insufficient real-image evidence for changing the default. |
| 12. Smoothing scale | Keep user controls/defaults; coarse auto smoothing and physical-width models remain planned experiments. |
| 13. Repeated weak preparation | Prepare crop-only candidates once, then apply each trial's strong-profile exclusions **before** weak deduplication. No stale cross-request cache and no accidental loss of neighbours when a strong peak drops out. |
| 14. Repeated geometry on chosen threshold | Reuse geometry-auto's selected geometry result. Also cache template/ratio prediction coordinates within the current FFT analysis only. |

## Local checks

The full suite passes: **169 tests** on local macOS/Python 3.14, including existing worker-spawn and batch tests. JavaScript syntax and whitespace checks pass. Ten new tests in `tests/test_review_fixes.py` cover:

- Two noisy HCP orientations with six profiles each and secondary weights 0.6× and 0.35×. Both reach refinement in fixed, shared-scale, independent a/c and overall+c/a modes. This verifies exploration, not mandatory acceptance of the weaker fit.
- Single-orientation input remains a single HCP result; supplementary seeds avoid repeated support/symmetry copies.
- Zone-alternative retention is identical between fixed and automatic scale paths.
- Weak candidates honour smoothing/floor, exclude strong profiles before deduplication, and do not mutate cached candidates.
- Weak preparation occurs once per auto analysis; geometry-auto does not repeat the selected geometry calculation.
- Prediction-coordinate caching preserves results.
- Three Gaussian-noise crops across manual/geometry-auto/rank-auto produce no passing crystal fits. This small control is not a calibrated false-positive-rate estimate.
- Three-profile reporting leaves the screen unchanged.

### Real-image regression recipe

Use original DM4 files for ST1221, ST1203, Ti_0274 and ST1156. For each 4096×4096 image and width `L` of 6 or 20 nm, use `n = round(L / pixel_x_nm)` and ROI `x = y = round(2048 - n/2)`, `w = h = n`. Enable HCP/BCC, select `auto_hcp_ratio`, retain current detector/scoring defaults (including 0.50 nm⁻¹ separation), and run manual, geometry-auto and rank-auto with image rendering off. This gives 24 cases. Labels below are software outputs, not independent ground truth.

| Image | Width | Manual | Geometry-auto | Dominant rank-auto |
| --- | ---: | --- | --- | --- |
| ST1221 | 6 nm | Insufficient | HCP | HCP |
| ST1221 | 20 nm | HCP | HCP | HCP |
| ST1203 | 6 nm | BCC | BCC | BCC |
| ST1203 | 20 nm | Unresolved | Unresolved | Unresolved |
| Ti_0274 | 6 nm | BCC | BCC | BCC |
| Ti_0274 | 20 nm | Unresolved | BCC | BCC |
| ST1156 | 6 nm | HCP | HCP | HCP |
| ST1156 | 20 nm | HCP | HCP | HCP |

Caching alone gave identical analysis data in all 24 cases after removing runtime and engine-version identifiers. The completed changes preserve all 24 labels and do not decrease the best HCP or BCC score in any case. This is a smaller, different set of crops than Claude's study; it does not reproduce that full study or establish accuracy. Direct diffraction is covered by existing synthetic/integration tests, not a new ST1144 real-image sweep here.

Timing is exploratory: one sequential baseline/cache/search run per case, without repeated statistical benchmarking. For the slowest baseline case (Ti_0274, 20 nm, rank-auto), elapsed time was about 3.25 s before changes, 2.59 s with caching alone and 2.76 s after supplementary seeds. Other cases became slower because more hypotheses are refined. The final correctness run overlapped the test suite and is not used for timing claims. No universal throughput improvement is claimed.

## Remaining limitations and next experiments

- Existing seeding still uses a bounded set of observed peaks (up to the first 16 in these search paths); additional orientation seeds are not exhaustive indexing.
- Per-phase retained-candidate limits and global-coverage acceptance can still hide or reject weak patterns. Rank-auto still optimizes a selected subset and can drop the weaker pattern entirely.
- A useful next scientific experiment is a fixed-pool/joint-pattern objective against single-crystal, known-mixture and noise controls, then the recorded image set. Do not simply sum the two best ranks, which may describe the same peaks.
- Detector alternatives should be compared across crop sizes, including ST1156 and the known A/B/A Ti_0274 region, before changing defaults. Subpixel uncertainty, watershed/integrated spot intensity, robust backgrounds and automatic smoothing remain experiments.
- Evidence pruning, warm starts, shared pair hypotheses and fewer threshold trials are further performance options; they are not implemented here. Search-changing shortcuts need validation under the eventual objective.
- Native Windows checks and a real same-phase two-orientation case remain outstanding. No architecture diagram changes were made.
